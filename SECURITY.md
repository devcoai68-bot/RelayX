# Security Policy

## Reporting vulnerabilities

Please report suspected RelayX vulnerabilities privately. Do not open a public issue with exploit details, secrets, packet captures, or proof-of-concept code.

Send a report to the project maintainers using the repository owner's preferred private contact channel. If no private channel is published, request one by opening a public issue that contains no sensitive technical details.

Include, when safely possible:

- affected version or commit;
- deployment mode and relevant configuration, with secrets removed;
- impact and exploitability assessment;
- reproduction steps or minimal proof of concept;
- logs or traces with tokens, keys, authorization headers, and bodies removed.

## Response expectations

Maintainers should acknowledge reports, investigate impact, prepare a fix when appropriate, and coordinate disclosure timing with the reporter. Security fixes should avoid unnecessary protocol, packet-format, crypto, replay, parser, or public API changes.
